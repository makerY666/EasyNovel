## 可以直接使用的操作

双击桌面 **EasyNovel** 快捷方式或根目录 **启动.cmd**，浏览器自动连接。更新后请先关闭旧启动窗口。选择作品 → 写作 → 添加章节 → 正文上方 **AI 写作** → 输入要求 → **直接写正文**。结果在中央预览，审核后选择记忆并确认入库。具体步骤见 [上手说明](USAGE.md)。

## 本轮修复

- 去掉架构师隐藏的 1024 Token 输出限制；截断恢复同时展示角色和模型的单次输出限制，明确区分总预算。
- 默认直接写正文，自动经过规划和审稿；指令卡、规划和技术日志有独立展示，不再伪装成正文候选。正文在中央展示，章节之间不会串稿。
- 提交前保护未保存编辑和输入版本；锁定段落不允许被全章改稿覆盖。打开历史不触发再次入库。
- 完成或过期候选可以针对当前前文提出修改要求；原稿、历史与账本保留。受影响章节允许审核修复，正式续写继续受影响检查保护。
- 模型读取作品介绍与风格。明确全章篇幅，逐场景分配；严重超长时最多额外压缩一次，之后重新审核，不进行无限改稿。
- 审稿区显示中文问题、摘要、严重性、建议和原文引用。未来风险与缺乏依据的评论不直接等同于已经发生的矛盾；关键问题增加证据复核，文体修改造成关键问题时回退并保留诊断。
- 记忆提取只从实际正文取证，不把计划变成事实；输出引用必须匹配原文。
- 不确定是否已经付费的调用无法通过更改输出限制绕开保护；重复启动复用已有实例，重启后更新会话令牌，无需手工复制。
- 导入任务跨页面和重启可恢复，目录自动更新；后台刷新保留未保存稿。暂停导入预留章节序号，手动新章与其他导入不会抢占。已完成任务不能重新暂停。
- 备份下载不再出现 `.zip.zip`；界面完成导出、下载和恢复验证。

## 记忆整理格式失败及恢复

后续任务在 `memory:chunk:1` 返回 `kind="speech"`，而合法表示应是 `kind="event"`、`source_type="speech"`。已付费的一次格式修复改对字段，但在合法 JSON 后附了修复说明，原解析器以 trailing characters 拒绝。此前通用错误提示只显示 ValidationError，未说明失败节点和字段。

解析器现可验证单个 JSON 后附说明的响应，仍拒绝多个 JSON 结果和不符合 Schema 的字段。新任务明确区分 kind 与 source_type，并在一次格式修复中提供失败字段。旧任务保留原提示版本，避免恢复时因提示变化重新支付已完成调用。其他节点的格式错误显示角色、调用及字段；记忆片段一次修复仍失败时，仅跳过该片段并显示来源段落范围警告，其他有效记忆和正文仍可审核，不把缺失记忆伪装成全文已核查。
