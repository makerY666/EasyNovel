# EasyNovel local API contract
Base /api/v1. Browser dev proxy /api to 127.0.0.1:8765. Desktop bootstrap `invoke('backend_config')` -> {base_url,token}. Header Authorization: Bearer token. Errors {detail: string|object}. IDs UUID strings. JSON arrays for list results unless pagination specified. All timestamps UTC ISO.

GET/PATCH /projects/{id}; patch {expected_revision,title?,description?,settings?}.

Every state-changing request advances project revision except draft saves, run creation/progress and derived indices. UI refresh project after canon or commit mutations. Automatic text extraction stays candidate. Default profile roles architect/planner/writer/continuity/editor/stylist/memory. No secrets in any response/log. Runtime errors remain visible; no demo success.

## Final integration additions

- `GET /projects/{id}/impact` returns persisted impact records. Impact now may have `source_record_id`, with nullable `source_chapter_id` / `version_id` for setting changes.
- `PATCH /records/{id}` returns a candidate replacement plus `impact`. `GET /records/{candidateId}/impact` refreshes that preview. Approving a replacement, or withdrawing confirmed canon, requires `impact_acknowledged:true` when affected chapters exist; withdrawal still requires a reason. Stale previews are rejected.
- Character `data.entity_id` remains stable through replacement. In a copied story branch, character entity IDs and references are remapped. A dependent memory whose evidence was withdrawn, superseded or becomes future information cannot be retrieved as active canon.
- `Provider.extra_body` allows validated vendor options such as `thinking` and `reasoning_effort`; it never contains the API key.
- `POST /projects/{id}/directives/parse` returns an asynchronous **Run**, with `artifacts.directive` when ready. `POST /projects/{id}/index` requires `token_budget` and accepts `branch_id`; `GET /index/{id}` reports progress.
- `POST /projects/{id}/search` explicitly performs paid query embedding plus validated semantic/FTS results: `{q,branch_id,story_time?,token_budget}`. GET remains free local search.
- `POST /runs/{id}/resume` accepts `{token_budget?,money_budget?,role_limits?:{role:number},provider_output_limits?:{provider_id:number}}`. Role limits must be 128–100000 and are clamped to the frozen provider output setting. Explicit provider output updates apply only to this run's snapshot, must be 128–100000 and below its context limit; model or provider identity changes require a new task. `artifacts.output_limit_info` identifies a truncated role and its effective, role and provider limits. Truncated calls retain their text, usage and finish reason and cannot be replayed as complete results.
- `RunInput.auto_approve_plan` defaults to false. Explicit true automatically selects the single initial plan and continues to prose review; it never approves core plot changes or commits prose/memory. Comparing three plans requires manual plan review.
- A core plot-changing revision resumes via `POST /runs/{id}/approve-plan {accept_change:true|false}`. Run artifacts contain `proposed_revision`. Confirming prose is asynchronous; wait until status `completed` before showing success.
- SSE text events use `event:'text'` with `{role,call_key,text}`. Usage has `cost_known`; false/missing cannot be presented as a zero bill.
- Project settings `token_budget` / `money_budget` cap cumulative project use. `chapter_token_budget` / `chapter_money_budget` cap cumulative calls for each chapter; null or omission means unlimited. Every retry and uncertain reservation is counted.
- Only one active writer task can own a chapter. AI saves compare both project revision and the input draft head. A competing manual edit leaves model artifacts preserved and refuses replacement.
- `POST /runs/{id}/revise {instruction,expected_revision}` creates a new `author_revision` Run from saved prose in an awaiting-review, completed or stale run. The current chapter head must still match that saved version. It loads fresh context, applies author feedback, performs at most one target-length compression when over 150%, audits and revises at most the profile's configured rounds, extracts candidate memory and awaits explicit final approval. A pending parent review is replaced but preserved in history. A blocked chapter can be repaired through this route; ordinary generation remains blocked. Core plot changes still interrupt for `accept_change`. Latest author instructions replace previous feedback in the task prompt; provenance remains in parent run history.
- `ReviewIssue.basis` separates actual conflict, missing cause, future risk, creative detail and preference; `quote` must identify current prose. Optional critical triage retains decisions in `artifacts.review_triage`; model judgments remain fallible. `artifacts.length_adjustment`, `before_length`, `style_rejected` and `rejected_style_reviews` explain bounded compression and rejected style changes. Updating a role limit or prompt cannot bypass an unresolved paid call for the same logical node.
- Browser launcher creates an authenticated local session and hands it to the UI through `#session=...`; the UI consumes and removes this fragment before API effects. Existing origin storage is refreshed on startup and same-page session changes. The session marker contains only a random local service token, never model credentials.
- `GET /projects/{id}/imports?branch_id=main` returns the latest 100 import jobs, excluding source text payloads. Pending import chapter numbers are reserved until completion, including paused or failed jobs, so manual creation and another import cannot occupy those numbers. Choosing a reserved number explicitly fails with a readable conflict.
