# EasyNovel 上手说明

本机双击桌面 **EasyNovel**，或 `D:\makerY\EasyNovel\启动.cmd`。浏览器会自动打开并连接。保留启动窗口；关闭窗口退出软件。更新代码后请关闭旧启动窗口，再启动，单独刷新网页不能更新后台。

端口被其他程序占用时会自动选择可用端口，无需手工修改。重复双击会打开已运行的同一工作台；首次启动期间连续点击也不会创建多个后台。新版手工启动的后台可被启动器识别并复用，同一作品库只允许一个后台进程。作品默认保存在 `%LOCALAPPDATA%\EasyNovel`，关闭窗口不会删除作品。

## 让 AI 写第一章

1. 选择作品，点击左侧 **写作**，用目录右上角 **＋** 添加章节，填写标题。
2. 点击正文上方 **AI 写作 · 打开作者导演**，保持 **直接写正文**。在 **本章创作任务** 写希望发生的事、主角、风格和全章篇幅。例如：

   > 写第一章，约2500字。主角在上学途中遇到一名神秘少女，两人因为遗失物产生冲突。第一人称，校园日常，轻松但对话有潜台词。先建立人物关系，不急着揭开少女身份。

3. 选择模型，确认任务预算，点击 **直接写正文**。系统自动规划、写作、审稿。正文会展示在中央 **正文候选预览**。规划和指令是单独成果，不会混进正文。
4. 查看审稿意见、展开原文证据。右侧 **候选记忆** 只勾选可信的内容，再点 **确认审核与 N 条记忆**。看到 **正文已确认入库**，目录显示 **已确认**，才算完成。
5. 添加第二章，输入本章推进方向。系统会检索已确认的前文与记忆；不必重复粘贴上一章。

如果尚无模型，到 **设置 → 模型连接** 添加服务地址、模型 ID 和 API 密钥。供应商密钥保存在系统凭据库。使用实际支持的模型 ID 和单次输出容量；连接测试会产生一次模型调用。

## 想改正文

右侧 **让 AI 按要求修改** 中填写具体问题，例如「删掉重复解释；先让角色听见消息，再根据消息行动；保持结局不变」，点击 **生成修改稿**。新任务读取当前前文，原候选保留在历史里。改稿也要重新审核和确认；改变核心事件时还会要求确认剧情变化。

手工改稿点中央 **返回编辑器**。**保存草稿** 只保存编辑内容，**确认入库** 才让它成为续写依据。锁定段落逐字保留。任务运行期间如果手工修改了输入稿，系统保留生成成果并拒绝覆盖新稿。

修改已确认的前章后，到 **导入与修复 → 影响与修复** 核查后章。受影响区域的正式续写暂停，但可以生成修改稿、编辑和审核修复。确认修复或填写核查说明后，再继续创作。

## 暂停时看什么

| 提示 | 含义与处理 |
| --- | --- |
| 单次回答达到输出上限 | 一次回答被截断；在 **调整额度并恢复** 中提高对应角色和模型的输出上限。1000000 的总预算不能自动增加每次回答长度。 |
| 任务 Token 预算不足 | 多轮调用累计或下一次预留超出任务预算；已有成果保留，调整总额度后恢复。 |
| 硬约束超过上下文容量 | 缩小场景或使用更大上下文的模型，不能静默丢掉硬约束。 |
| 上次调用结果未确认 | 可能已经付费；改输出上限也不会自动重发。核对供应商账单后，显式启动新任务。 |
| 作品或稿件已变化 | 使用当前正文重新提出改稿要求，避免旧任务覆盖新内容。 |

任务总额度包含规划、写作、审稿和修改，并非预期正文 Token 数量。金额未知只统计 Token，不能将 `cost:0` 理解为免费。单次篇幅目标是指导值；一次压缩不满足要求时会保留原稿并提示作者。

## 导入、备份与导出

**导入与修复 → 导入长篇** 选择 TXT / Markdown，检查分章预览，可调整章节边界，再导入。导入的自动记忆仍要核查，不能当成作者原意。

导入开始后可以切回写作。目录会随导入更新，返回导入页可查看原任务、暂停或继续；重开软件后任务记录仍在。暂停任务的章节序号会保留，新建章节和其他导入不会占用这些序号。

**备份导出** 可以创建完整项目备份、下载 ZIP，或导出已确认正文 TXT / Markdown。恢复会覆盖整个本地库，操作前软件另行备份。模型密钥不包含在备份中。

当前提供浏览器工作台的一键启动；独立 Windows 安装包仍受本机应用程序控制策略阻碍，尚未交付。文学质量需要作者读稿，模型审稿不能保证发现所有矛盾。
