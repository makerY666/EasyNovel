# 首版实现与验收记录

日期：2026-10-02。此记录描述实际完成情况，不代表 A—D 专业版本已全部验收。

## 已实现的可运行闭环

- 本地作品管理、按需章节目录、Tiptap 编辑、自动保存草稿、稳定段落 ID 与锁定、版本差异、TXT/Markdown 导入导出。
- SQLite WAL、Alembic、统一正式提交通道、正文与选中记忆原子提交、幂等键及作品修订号校验；生成期间草稿改变时保留任务成果并拒绝覆盖。
- 人物、状态、认知、关系、规则、事件、伏笔、计划和导演指令。保留来源类型、版本、段落、故事时间、记录时间和状态。候选与未来计划不混入确认事实。
- 中文预分词 FTS、实体别名、时间/分支过滤、显式依赖、回收窗口召回；LanceDB 按嵌入模型分库，查询时复核当前来源。无嵌入模型可继续使用全文与结构化检索。
- LangGraph 持久化作者审核：架构建议 → 场景方案 → 逐场景生成 → 两位独立编辑并行审核 → 最多两轮修改 → 文体修订与复核 → 记忆预览 → 选择性确认。人物视角与时间按场景组装上下文。
- 模型按职责配置、供应商推理选项、冻结配置快照、调用账本、任务与作品预算预留、输出截断暂停、格式修复一次、结果不确定时避免重复付费、SSE 断线补读。
- 局部改写、完整备选分支、整章采用、前文和已确认设定的修改/撤回影响检查、后续章节阻塞、生成修复候选和作者核查解除。
- 系统凭据库保存密钥；本地服务只监听回环地址并要求会话令牌；迁移前备份、手动完整备份与恢复，原始旧库只读导入。
- Tauri Windows 壳、Python sidecar 生命周期、健康检查、NSIS 配置与 CI 构建脚本已编写。

## 实际验证

后端 24 项测试通过，覆盖原子提交回滚、重复提交、过期输入、长期伏笔、别名、时间和认知过滤、锁定段落、分支隔离、预算暂停、有限修改、断点恢复、结果不确定的调用、导入候选、LanceDB、备份恢复及设定影响保护。

前端生产构建与 TypeScript 检查通过，交互测试覆盖导演指令、编辑锁定、记忆选择、计划变更确认、预算恢复及设定影响确认。最终 9 项前端交互测试通过。浏览器手动验收了新建作品、添加章节、保存草稿、确认正文、带来源的证据检索与工作台布局。

使用本机环境变量 `DEEPSEEK_API_KEY` 真实调用 `deepseek-flash`，隔离测试完成了规划、正文、并行审稿、文体修订、候选记忆与确认提交。累计输入 43873、输出 13251，共 57124 tokens；包含失败的截断结果和格式修复，预留最终清零。供应商单价未配置，金额未知，报告中的旧字段 `cost:0` **不表示调用免费**。报告和正文在 `artifacts/live-smoke/`。最后的逐场景上下文与并发保护增强另经离线测试，未重复计费执行整套真实模型测试。

`scripts/benchmark.py` 构建 5000 章、14999994 字正文、100001 条记录和 105001 个 FTS 文档。Windows 11 / Python 3.12.14 上，预热后：

| 项目 | P95 | 样本 |
| --- | ---: | ---: |
| 后端章节读取及 JSON 编码 | 0.35ms | 50 |
| 本地全文证据检索 | 1.25ms | 50 |
| 本地上下文组装 | 67.53ms | 20 |

第 18 章的玉佩证据在第 5000 章上下文被召回。报告位于 `artifacts/benchmark/latest.json`。这是固定合成数据与少量查询的后端测量；不包含 UI 端到端时间、远程嵌入/重排、导入期间完整内存测量，也不能推导出所有检索任务的 95% 召回率。

## 阻碍与未完成验收

本机 Windows 应用程序控制策略以错误 4551 阻止 Rust 自动生成的构建程序运行。Python PyInstaller 已成功生成后端 exe，但新版 exe 的启动也被系统策略阻止。因此 Tauri 二进制编译、独立安装包、安装升级、关闭/崩溃后的子进程清理、中文安装路径与无开发环境运行 **尚未验证**。没有修改或绕过系统安全策略。Windows CI 已配置，但未创建远程仓库发布或声称 CI 已运行。

以下专业版要求还需继续实现或验证：

- 模型能力测试目前实际验证文本和 JSON 提示输出；流式、原生结构化输出、工具能力与真实上下文容量的独立探测未完整实现。
- 摘要支持来源记录与章节抽取，尚无自动重建场景—章—弧—卷—全书五级摘要的完整流水线；分层规划当前产出审核建议与场景卡，尚未实现全书计划到各卷的自动维护和每弧重评闭环。
- 时间和认知查询支持过滤；多时间点章节在修订后重新定位所有状态变化，仍依赖候选记忆和作者审核，不能宣称自动发现全部矛盾。
- 修复正文会生成带审稿的候选版本，但尚未自动形成逐章“修复正文 + 完整新记忆 + 索引重建”的统一修复审核界面。
- 当前支持任务/章节/作品预算；个人风格样例库、人物关系图/时间线可视编辑、专用简单/专业模式切换尚未完整实现。
- 前端接口类型当前按契约维护，尚未全部切换为 OpenAPI 生成的响应类型。全文索引的提交更新仍集中执行，需要进一步拆分派生索引任务以缩短超长章节的写事务。
- 95% 必要证据召回率需在独立、包含误召回与未来泄露的故事基准上测量。长篇导入后台交互、常规内存、UI P95 仍需完整压力验收。
- 30 项任务 × 至少 3 位读者/编辑的匿名偏好评测、65% 偏好率和百章实写验收未执行，需真实读者参与。数千章的合成规模测试不替代文学评价。

阶段结论：已经具备可使用与继续开发的本地创作闭环，尚不能将其命名为完成全部 A—D 验收的专业发行版。

## 2026-10-03 回归更新

本轮后端 43 项、前端 40 项测试与生产构建通过；浏览器验证了直接写正文、第二章、作者反馈修改、导入目录自动更新、任务恢复、备份下载/恢复、自动鉴权和一键启动生命周期。受影响单章现已支持“作者修改 → 正文和候选记忆审核 → 原子提交”，批量修复及五级摘要自动维护仍未完成。

三种题材各两章使用真实 `deepseek-flash` 走完整工作流，经过读稿反馈与逐句编辑后确认。原始模型结果仍有漏审问题，不能宣称达到高水平作家或匿名偏好目标。浏览器启动的退出与子进程清理已验证；Tauri 独立安装包和安装验收仍受上述系统策略阻碍。详细结果、费用范围和样章链接见 [本轮报告](QA-2026-10-03.md)。
