# 第一章生成与成果可见性修复

遵守 DESIGN.md 的现有颜色、布局、字体及证据轨道，不重新设计工作台。

## 目标
作者选择章节，输入想写的内容，点击「直接写正文」，系统完成规划、写作、审稿，中央自动显示正文候选；作者最终确认入库。正式事实和锁定段落仍由提交服务保护。

## 流程与状态
- 默认「直接写正文」模式，发送 auto_approve_plan=true、candidate_count=1。提示「自动完成规划、写作和审稿；正文由你确认入库」。第二模式「先审核计划」，沿用当前审核流程。第三模式「整理创作指令」，明确提示仅产生约束卡，不写正文。移除容易误操作的解析复选框。
- 模型未选择且只有一个可用模型时自动选择；任务输入提供第一章示例提示。不替用户自动付费发起任务。
- 实际 artifacts.draft 出现时提供「查看正文」并自动打开中央只读候选预览，预览保留换行和小说排版，显示尚未入库及返回编辑器。保持 NovelEditor 挂载，不能丢失未保存文字。跨作品、跨章节成果不得盖到当前章节。
- 只有 artifacts.draft 能显示为正文。架构、指令、规划、记忆的 SSE text 均不能误标正文；流式 JSON 不直接作为小说展示。高级技术日志可折叠。
- 指令完成反馈「创作指令已整理，请到故事资料核对候选约束」；正文待审核反馈「正文已生成，请查看正文并确认入库」；正文提交完成「正文已确认入库」。取消泛用的「任务已完成，成果已保存」。
- 暂停显示当前角色、人类可读阶段、具体原因。区分「任务总 Token 额度」和「单次回答输出上限」。恢复弹窗允许提高角色输出上限以及模型输出上限，分别显示当前配置值。不能把输出截断提示成总预算耗尽。
- Run.request 增加 kind、auto_approve_plan，Run.artifacts 可含 output_limit_info={role,maximum,provider_max_output,role_max_output,requested_output_limit,model,context_limit}。恢复接口允许 provider_output_limits={provider_id:limit}；role_limits 仍原有。

## 验收与可访问性
清晰按钮和标签、键盘可操作、只读预览有可识别标题。解析任务及非 writer 文本流绝不出现正文候选；快速模式提交正确标记；真实正文自动预览同时保护已有草稿；暂停提示与恢复字段不混淆两种额度。重连和历史任务仍可打开正文。遵守现有 tokens，无营销文案，无新增装饰卡。

## Preflight
既有身份锁定；覆盖初始、运行、暂停、失败、候选及入库状态；简单入口位于任务表单首部；预算单独说明；不默默覆盖草稿；颜色不作为唯一状态标识。自评：层级4、一致性4、可访问性3、状态覆盖4、文案4、克制4。

## Build handoff
react_vite_tailwind_engineer 实现 apps/web 的表单、结果预览、反馈、恢复及有意义的回归测试；根代理实现后台契约及截断修复。

## 一键启动
根目录启动.cmd 自动打开浏览器；启动器通过 #session 参数交接每次启动的本地会话令牌。前端只读取显式 session 参数，写入现有 sessionStorage 并立即移除地址栏片段。不通过查询字符串发送令牌，不改模型配置或作品。默认模型缺失时给出设置入口；重复启动检测已运行实例，不生成第二个后端或覆盖当前令牌。开发服务器端口检查与就绪检查完成后才打开浏览器；错误保留可读提示。

## 作者提出改稿要求
正文待确认和已完成任务展示折叠的「让 AI 按要求修改」，输入具体修改要求，点击「生成修改稿」。发送 POST /runs/{rid}/revise {instruction,expected_revision}，返回新的 Run 并选中。提交前沿用手稿保存保护。界面说明使用原任务的模型与预算配置，修改稿需重新确认入库，不悄悄覆盖正式正文。若父候选仍待确认，新任务取代其待审状态，但历史成果保留。模型与角色单次上限不足仍按原恢复规则处理；核心事件变化仍需要明确审核。长度调整和润色退回给出可读提醒。

## 导入后切页与任务恢复
ImportCenter 从 GET /projects/{id}/imports?branch_id 恢复当前分支最近持久化任务，显示进度和暂停/恢复；离页不丢失任务。完成时刷新作品与目录。导航到写作须先通过现有草稿保存保护再刷新目录，不能为了刷新后台导入而覆盖未保存正文。后台导入未结束仍显示可重新查看的导入进度，不要求用户猜测是否需手点刷新。后端保护导入预留章序，追加章节使用预留范围以后的编号。
